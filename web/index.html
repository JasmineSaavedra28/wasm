Integración sin glue code

El módulo C exporta memory y funciones que reciben un offset. No hay Emscripten, ni wasm-bindgen, ni un archivo JavaScript intermedio. 

const { memory, apply_grayscale } = instance.exports;

// El búfer vive una sola vez en la memoria lineal del módulo.
const ptr = 65536;
new Uint8Array(memory.buffer, ptr, imageData.data.length).set(imageData.data);

apply_grayscale(ptr, imageData.data.length / 4);   // in-place

// Al pintar, se lee de la misma región (una copia inevitable hacia el canvas).
imageData.data.set(new Uint8Array(memory.buffer, ptr, imageData.data.length));
list<u8> (ptr: i32, len: i32)

Los bytes viven en memoria lineal; no se serializan.

string (ptr, len) UTF-8

El contrato WIT

            wit/grayscale.wit
          

          

            WIT describe tipos, no memoria. La ABI canónica es la traducción entre esos tipos y
            los i32/ptr del módulo core. En producción, wit-bindgen o
            jco generan este código; acá se hace a mano para que sea visible.

Lectura y costo

              gas intrínseco
            

            

            

            

            

              4 gas por byte cero y 16 por byte distinto de cero, sin contar ejecución ni
              almacenamiento. Un frame de 1 MB ya supera la mitad de un bloque de 30 M de gas.

Dos ABIs, dos objetivos

          

            

              
                

                  
                  ABI canónica (Component Model)
                  ABI de Ethereum
                

              
              
                

                  Unidad
                  tipos WIT: list, string, record, variant
                  palabras de 32 bytes + selector de 4 bytes
                

                

                  Dirección
                  host ↔ módulo, misma memoria lineal
                  cliente ↔ EVM, datos serializados
                

                

                  Costo
                  un puntero y un largo; cero copias si se diseña bien
                  16 gas por byte distinto de cero
                

                

                  Uso típico
                  píxeles, audio, buffers grandes
                  metadatos, permisos, hashes, pruebas
